## Key handling rules

- Every key pair is generated by the CLI with `autogenerate-new-keypair save-to-legacy-keychain`, which writes it into the local credentials store (`~/.near-credentials/testnet/`). Nothing is typed, pasted, echoed, logged or committed.
- Every transaction is signed with `sign-with-legacy-keychain`. Never use `sign-with-plaintext-private-key`, `sign-with-seed-phrase`, `print-to-terminal`, `export-account` or `--teach-me` (it prints full RPC bodies).
- Never `cat`, `ls -la`, copy or upload files in the credentials store. Only public keys (`ed25519:...`) may appear in output, notes or `deployments/testnet.json`.
- If any CLI version prints a seed phrase or private key for a command below, stop, do not copy the output anywhere, and report it (UNVERIFIED: the docs show only "The data for the access key is saved in the keychain" for these commands).

The function-call key's allowance (0.25 NEAR) caps the agent's gas spend. Agent calls use 100 Tgas because 300 Tgas costs more than that 0.25 NEAR allowance.
